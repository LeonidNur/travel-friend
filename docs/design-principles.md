# Принципы дизайна

Этот документ фиксирует принятый подход к дизайну Travel Friend. Он нужен для того, чтобы UX, UI и разработка двигались в одном направлении и не расходились по мере роста продукта.

## Базовый подход

- Сначала UX, потом UI.
- Сначала wireframes, потом визуальный стиль.
- Сначала дизайн-система, потом отдельные экраны.
- Все экраны собираются из общей библиотеки компонентов.
- Дизайн развивается параллельно с разработкой, а не после неё.

Идея проста: сначала мы понимаем пользовательский сценарий и структуру интерфейса, затем закрепляем визуальный язык, после этого масштабируем экраны через общие компоненты. Так проще поддерживать согласованность и быстрее развивать продукт без хаоса в интерфейсах.

## Рекомендуемый порядок работы дизайнера

1. Дизайн-система
2. Поиск попутчиков
3. Карточка пользователя
4. Профиль
5. Анкета путешественника
6. Личный чат
7. Групповой чат
8. Карточка поездки
9. AI внутри чата
10. Маршрут
11. Настройки
12. Онбординг

## Что важно помнить

- Один и тот же паттерн должен выглядеть одинаково во всех местах.
- Новые экраны не должны ломать уже принятые визуальные и поведенческие решения.
- Если появляется новый компонент, он должен быть пригоден для повторного использования.
- Дизайн должен помогать разработке, а не создавать отдельную параллельную реальность.
