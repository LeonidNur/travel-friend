# Устойчивые правила Codex

Этот документ содержит ограничения, которые действуют независимо от типа задачи. Порядок работы, проверки и handoff описаны в [Codex task protocol](codex-task-protocol.md).

## Границы решений и изменений

- Не принимай продуктовые или архитектурные решения вместо команды.
- Не расширяй согласованный scope, не меняй несвязанные файлы и не добавляй зависимости без явного разрешения.
- Находки вне scope фиксируй как risk/TODO для review; не исправляй их в текущей задаче.
- Не переписывай `README.md` без явного указания.
- Для `docs-only` не меняй приложение, тесты, migrations, CI, конфигурацию или package manifests.

## Границы доверия и безопасности

- Telegram authentication проверяется сервером через raw `initData`; `initDataUnsafe` не является доказательством identity.
- Не раскрывай и не коммить секреты, credentials или персональные данные.
- Не выводи Supabase schema из frontend view models; фактический физический контракт проверяй по migrations и текущей реализации.
- Production/provider, destructive и credential-changing actions выполняются только при явном согласовании и в разрешённом scope. Наличие инструкции или успешных локальных checks само по себе не является approval.
