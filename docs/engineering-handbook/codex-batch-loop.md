# Controlled batch loop

Это отдельный режим для набора маленьких задач, который пользователь заранее согласовал как одну очередь и один результат. Batch не является режимом по умолчанию. Каждый пункт выполняется по [обычному Codex task protocol](codex-task-protocol.md); здесь описано только управление очередью.

## До начала

- Зафиксируй согласованные пункты и их порядок. Для каждого запиши цель, scope, критерий результата и применимые checks.
- Все пункты должны вести к одному согласованному результату. Независимые изменения, которым нужны отдельные PR, разделяй на отдельные задачи/batch.
- Не подменяй неясный пункт самостоятельно выбранной задачей и не расширяй состав после согласования.

## Состояния и переходы

У каждого пункта ровно одно состояние:

- `pending` — ожидает очереди;
- `in_progress` — сейчас выполняется; одновременно активен только один пункт;
- `passed` — результат достигнут, применимые проверки завершены по task protocol, итог записан;
- `blocked` — выполнение остановлено по правилу остановки из task protocol;
- `skipped` — только пользователь явно исключил пункт и подтвердил причину.

Начинай следующий пункт только после `passed` предыдущего или `skipped`, явно подтверждённого пользователем. `blocked` останавливает весь batch: остальные пункты остаются `pending`. Автоматически пропускать пункт нельзя.

## Итог batch

Веди компактный queue log: состояние и результат каждого пункта, а также причина `blocked` или подтверждённого пользователем `skipped`. Финальный отчёт сохраняет исходный порядок, состояния, краткие результаты и общие риски; подробный формат проверок определяется task protocol.

Batch не разрешает автоматическое расширение scope, commit, push, merge, deploy или production/provider actions. Для них действуют те же границы согласования, что и для обычной задачи.
