# Рабочий процесс

Работа начинается с человеческого обсуждения цели, границ и рисков. Для неоднозначных или архитектурных вопросов команда принимает решение до передачи задачи в реализацию. Задача для Codex фиксирует согласованный scope и критерии приёмки.

## Исполнение, review и Git

Codex выполняет задачу по [Codex task protocol](codex-task-protocol.md) и передаёт diff с результатами проверок и оставшимися рисками на human review. Codex сам не делает commit. После review Леонид решает, создавать ли commit.

Правила Git/PR для проекта задаются здесь; generic skill examples их не переопределяют. Обычные feature/docs PR направляются в `develop`. Проверка и одобрение PR предшествуют merge по решению ответственных людей. Promotion из `develop` в `main` остаётся отдельным release decision; этот документ не меняет branch policy.

Одна задача должна давать один связный reviewable результат. Независимые изменения с отдельными PR оформляются отдельными задачами. Batch допустим только для заранее согласованной связной очереди и выполняется по [controlled batch loop](codex-batch-loop.md).

## Вход нового разработчика

1. Прочитать `README.md` для обзора проекта.
2. Открыть Engineering Handbook и [roadmap](../roadmap.md), чтобы найти процесс и актуальный этап.
3. Получить задачу с согласованными scope и критериями приёмки.
4. Подготовить feature/docs branch и выполнить работу в её границах.
5. Передать diff на review; для обычного feature/docs PR целевая ветка — `develop`.

## Диагностика проблемы

Используй короткий цикл, чтобы проверить причину до исправления:

```text
Диагностика
→ гипотеза
→ минимальный эксперимент
→ исправление в scope
→ применимые проверки по Codex task protocol
→ human review
```

Если причина неясна, нет прогресса или исправление выходит за scope, остановись с диагностикой и условием продолжения. Не делай commit частью этого цикла.
