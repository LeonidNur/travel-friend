# Travel Friend — Codex Rules

Travel Friend — Telegram Mini App MVP для поиска попутчиков и совместного планирования путешествий с помощью ИИ.

ChatGPT используется для продуктового мышления, архитектуры, планирования и декомпозиции. Codex используется для реализации небольших задач с чётким скоупом.

## Как работать

Перед изменениями Codex читает существующие файлы, показывает короткий план и перечисляет файлы, которые собирается изменить. Для docs-only задач он не меняет код приложения и не трогает `app/`, `components/`, `lib/`, `package.json` или `package-lock.json`.

Во время работы Codex держится в пределах задачи, не делает изменения «заодно», не добавляет зависимости без разрешения и не переписывает `README.md` без явного указания. Подробные правила процесса и приоритеты команды лежат в `docs/engineering-handbook/`.

После изменений Codex кратко объясняет, что сделал и почему, затем запускает нужные проверки вроде `typecheck` и `build`, если они доступны и уместны для задачи. В конце он перечисляет оставшиеся риски и TODO, если такие есть.

## Документация

Документация проекта по умолчанию ведётся на русском языке. `README.md` остаётся главным документом проекта и не должен сокращаться или переписываться радикально без явного разрешения.

## Базовые правила качества

Код и изменения должны оставаться простыми, понятными и проверяемыми. Предпочтение отдается небольшим фокусным диффам, ясным типам и отделению frontend, backend, database и AI-логики друг от друга.

## Безопасность

Нельзя раскрывать секреты на клиенте, доверять `initDataUnsafe` для аутентификации или коммитить чувствительные значения вроде API keys, bot tokens и Supabase service role key. Telegram Mini App auth должна проверяться на сервере через raw `initData`.
