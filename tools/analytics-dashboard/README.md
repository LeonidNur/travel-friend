# Travel Friend Analytics Dashboard

Отдельная локальная командная панель на Streamlit и Plotly. Она не является частью Telegram Mini App, не подключает PostHog и не отправляет внешнюю телеметрию. По умолчанию открываются синтетические данные с постоянной пометкой **DEMO**.

## Установка и запуск на Mac

Нужен Python 3.11 или новее и `uv`.

```bash
cd tools/analytics-dashboard
uv sync --frozen --all-groups
uv run streamlit run app.py
```

Панель слушает только `127.0.0.1:8501`; Streamlit usage statistics отключены. Откройте адрес, показанный в терминале, в браузере.

## Обновление данных

1. В панели выберите «Импорт агрегатов».
2. Загрузите JSON или CSV с точной схемой ниже. Файл обрабатывается в памяти, максимальный размер — 1 MB. Имя файла не используется как путь.
3. Настройте период. Все даты и календарные недели считаются в UTC.

Поддерживаемые поля CSV:

```text
period_type,period_start,metric,value
```

`period_type` принимает `day`, `week` или `snapshot`. Поле `metric` ограничено утверждённым списком из агрегатов; поля и строки с ID, текстом сообщений, маршрутами, профилями, JSON или произвольными свойствами отклоняются. Дневные интервалы должны включать все дни, в том числе пустые с нулём; сообщения должны сходиться: `messages_all = messages_user + messages_system`.

JSON использует ту же таблицу `metrics` и поля `schema_version: 1`, `generated_at_utc`, `source_label` (только метка, не подтверждение происхождения). Допустимые метрики:

- `day`: `new_users`, `matches_created`, `messages_all`, `messages_user`, `messages_system`, `trips_created`, `proposals_created`, `proposals_accepted_applied`;
- `week`: `wcat`, уникальные Trips с accepted + applied Proposal за UTC-неделю;
- `snapshot`: `registered_accounts_ever`, `registered_accounts_not_deleted`.

Импорт всегда помечается **ИМПОРТИРОВАННЫЕ АГРЕГАТЫ**: подпись внутри файла не считается доказательством, что числа настоящие или получены из SQL. Демонстрационный режим всегда показывает **DEMO**. DAU, MAU и retention не выводятся, потому что надёжной истории значимых действий пока нет. Discover views/decisions тоже не выдумываются: в текущем SQL-источнике их нет.

Пустые или отсутствующие в источнике метрики отображаются как «Нет данных», а не как ноль. Для существующего периода нулевые дни передаются явно. WCAT включает полные UTC-недели, пересекающие выбранный период; показатель считает уникальные Trips, а не число Proposal. Пользовательские итоги — текущий snapshot на дату последнего отчёта, он показывается независимо от выбранного периода и не является историческим состоянием на его конец.

## Экспорт агрегатов из SQL

SQL-экспорт — отдельная ручная команда; панель никогда не открывает соединение с БД и не читает DSN. Запросы находятся в `sql/` и выдают только агрегаты. Выполняются фиксированные параметризованные SELECT в `REPEATABLE READ READ ONLY` транзакции с ограничением времени. Не передавайте приложению `service_role` или суперпользовательский DSN.

Для однократного экспорта оператор отдельно задаёт переменную окружения с учётной записью, имеющей только необходимые права чтения, и явно подтверждает read-only target. Не сохраняйте URL/пароль в файлах репозитория или shell history; production export требует отдельного разрешения и preflight.

```bash
cd tools/analytics-dashboard
read -s TRAVEL_FRIEND_ANALYTICS_READONLY_DATABASE_URL
export TRAVEL_FRIEND_ANALYTICS_READONLY_DATABASE_URL
uv run python sql_export.py \
  --confirm-read-only-source \
  --start 2026-10-01 \
  --end 2026-10-31 \
  --format json \
  --output ./travel-friend-aggregates-2026-10.json
unset TRAVEL_FRIEND_ANALYTICS_READONLY_DATABASE_URL
```

Перед запуском проверьте базу и учётную запись; команда не выбирает production автоматически. Существующий файл не перезаписывается. JSON/CSV результат можно вручную загрузить в панель. Проверка соединения или выгрузки в рамках обычного запуска панели не производится.

## Экспорт отчёта для инвесторов

В боковой панели скачайте CSV или JSON для выбранного периода. Файл содержит только временные периоды и агрегированные числа, без пользовательских строк и идентификаторов. До отправки проверьте период, подпись источника и отсутствие **DEMO**; не трактуйте импортированную метку как верификацию происхождения. Внутренние агрегаты остаются чувствительной деловой информацией.
